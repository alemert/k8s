# Root Makefile and Installer Coverage

The three installers cover parts of the root `Makefile`, but they are not complete replacements.

| Area | Root `Makefile` | Installer coverage | Coverage |
| --- | --- | --- | --- |
| etcd | Delegates installation to `installer/etcd` | Packages and installs `etcd`, `etcdctl`, and the systemd unit | >100% |
| Control plane | Generates certificates, kubeconfigs, encryption config, and deployment artifacts | `installer/control` packages and installs those artifacts, control-plane binaries, and services | 99% |
| Worker/client TLS | Generates node and kube-proxy certificates centrally and deploys them | `installer/client-ssl` generates a kubelet certificate locally and creates worker kubeconfigs | 50% |
| TLS generation | Implemented centrally in the root `Makefile` | `client-ssl` partially duplicates this for worker credentials | |
| Kubeconfig generation | Implemented centrally in the root `Makefile` | `control` consumes control-plane kubeconfigs; `client-ssl` generates worker kubeconfigs | |
| Encryption config | Generated by the root `Makefile` | Included and installed by `control` | |
| Deployment orchestration | Handles host preparation and invokes installers | Installers perform local installation and service startup | |

## Etcd coverage gaps

The etcd installer covers the complete etcd installation flow defined by the root `Makefile`. There are no known missing installation steps:

- The root `Makefile` remains responsible for building, copying, and remotely executing `etcdinstaller`.
- The installer deploys the single-node etcd configuration provided by `etcd.service`; multi-node or TLS configuration is not included in the current setup.

## Control plane coverage gaps

The control-plane installer covers the core installation. The following items remain outside its scope or are still root `Makefile` responsibilities:

- `admin.kubeconfig` is intentionally deployed separately by the root `Makefile`; it is not part of the control-plane installer bundle.
- `kube-apiserver-to-kubelet.yaml` is bundled but not applied by the installer.
- Certificates, kubeconfigs, and the encryption configuration are generated by the root `Makefile`; the installer only packages and installs them.

## Worker/client TLS coverage gaps

The client-SSL installer covers the kubelet credential flow, but the kube-proxy flow is incomplete:

- `kube-proxy.crt` and `kube-proxy.key` are referenced when generating the kube-proxy kubeconfig, but they are not generated, bundled, or installed by `installer/client-ssl`.
- As a result, kube-proxy kubeconfig generation cannot complete successfully on a fresh worker installation.
- The root `Makefile` still generates the worker and kube-proxy credentials centrally; the client installer uses a different local-generation approach for the kubelet only.

## Main overlap

- The root `Makefile` explicitly builds the etcd and control installers in its installer targets.
- It does not invoke the `client-ssl` installer, although [`installer/README.md`](installer/README.md) documents it as part of the installation flow.
- The control installer mostly consumes files generated under `var/ssl`, `var/kube`, and `var/encrypt`; it does not replace certificate or kubeconfig generation in the root `Makefile`.
- The client-SSL installer overlaps with the root worker TLS and kubeconfig targets, but uses a different model: credentials are generated locally on each worker instead of centrally and copied over.
- The client-SSL installer appears incomplete for kube-proxy certificates: it references `kube-proxy.crt` and `kube-proxy.key`, but does not generate them itself.

## Responsibility split

1. The root `Makefile` generates cluster artifacts and handles deployment orchestration.
2. The etcd installer provides self-contained etcd installation.
3. The control installer provides self-contained control-plane installation using root-generated artifacts.
4. The client-SSL installer provides a partial alternative to the root worker credential deployment flow.

The largest functional overlap is between the root TLS/kubeconfig targets and `installer/client-ssl`. The control installer is primarily a packaging and installation layer around artifacts produced by the root `Makefile`.
