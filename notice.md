# Root Makefile and Installer Coverage

The three installers cover parts of the root `Makefile`, but they are not complete replacements.

| Area | Root `Makefile` | Installer coverage |
| --- | --- | --- |
| etcd | Delegates installation to `installer/etcd` | Packages and installs `etcd`, `etcdctl`, and the systemd unit |
| Control plane | Generates certificates, kubeconfigs, encryption config, and deployment artifacts | `installer/control` packages and installs those artifacts, control-plane binaries, and services |
| Worker/client TLS | Generates node and kube-proxy certificates centrally and deploys them | `installer/client-ssl` generates a kubelet certificate locally and creates worker kubeconfigs |
| TLS generation | Implemented centrally in the root `Makefile` | `client-ssl` partially duplicates this for worker credentials |
| Kubeconfig generation | Implemented centrally in the root `Makefile` | `control` consumes control-plane kubeconfigs; `client-ssl` generates worker kubeconfigs |
| Encryption config | Generated by the root `Makefile` | Included and installed by `control` |
| Deployment orchestration | Handles host preparation and invokes installers | Installers perform local installation and service startup |

## Main overlap

- The root `Makefile` explicitly builds the etcd and control installers in its installer targets.
- It does not invoke the `client-ssl` installer, although [`installer/README.md`](installer/README.md) documents it as part of the installation flow.
- The control installer mostly consumes files generated under `var/ssl`, `var/kube`, and `var/encrypt`; it does not replace certificate or kubeconfig generation in the root `Makefile`.
- The client-SSL installer overlaps with the root worker TLS and kubeconfig targets, but uses a different model: credentials are generated locally on each worker instead of centrally and copied over.
- The client-SSL installer appears incomplete for kube-proxy certificates: it references `kube-proxy.crt` and `kube-proxy.key`, but does not generate them itself.

## Responsibility split

1. The root `Makefile` generates cluster artifacts and handles deployment orchestration.
2. The etcd installer provides self-contained etcd installation.
3. The control installer provides self-contained control-plane installation using root-generated artifacts.
4. The client-SSL installer provides a partial alternative to the root worker credential deployment flow.

The largest functional overlap is between the root TLS/kubeconfig targets and `installer/client-ssl`. The control installer is primarily a packaging and installation layer around artifacts produced by the root `Makefile`.
